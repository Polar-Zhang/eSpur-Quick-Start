# eSpur 设备模式与控制边界

先明确站点、控制主机、实例、PDU 物理口组、服务名、运行目录和代码版本。lab 与 Studio 的 PDU
可能同为 `192.168.0.163`，不能仅凭地址识别对象。Studio A/B 的历史记录分别对应 1–4、5–8
口和不同实例；实际进程位置与运行状态须核验。全网关系见[拓扑台账](<../2-Overlay NetWork-Quick Start-Skill/references/topology.md>)。

## 闸门语义与当前限制

当前**仓库代码**中，各实例目录的 `SWITCH_DISABLED` 只拦截 `purpose=auto` 的真实 SET；
显式 `manual` 和 `safety` 不受该检查。部分实际安全补开调用未显式传入 `safety`，默认
走 `auto`，可能也会被闸门拦截。因此不能把 test 理解为“禁止一切 PDU 变更”，也不能
仅凭标记保证安全补开可用。远端设备代码版本与物理状态须分别确认。

当前实机控制实现仍有待修复问题：同数量换组时逐口顺序可能先关后开，安全检查和 SET
锁边界也需改进。ACK 或命令态不等于物理继电器动作，尤其对控制 OID 不可读的 PDU。
**不得把手动逐口开关、断电重启或实机遍历当作常规验收。**

## 现有模式脚本暂不可用

本仓库 `scripts/espur-switch.sh` 在处理任何参数之前先 enable/start 服务，之后才处理
`test` 标记；无参数状态查询也会启动服务。`live` 先删除标记再检查可选网络配置；脚本
默认只指向 1–4 口的 `espur-algorithm`，不能代表另一个实例。错误时也可能误报成功。
**在修复并完成隔离验证前，不要执行它的无参数、test 或 live 模式，也不要复制到设备。**

只读核对可查看目标 unit 的状态、WorkingDirectory、ExecStart 和对应实例目录中的标记；
标记存在只能说明该文件存在，不能证明正在运行版本会按预期执行。所有真实开关、服务
启停或网络改动都应在明确要求、确认现场负载与恢复方式之后另行实施；本文件不提供
未经验证的替代切换命令。

## 手动保持时间

当前仓库 `src/psu.py` 从环境变量 `ESPUR_MANUAL_HOLD_SECONDS` 读取保持时间，默认 0；
仅在 `config.ini` 写 `manual_hold_seconds=900` 不会使该工作区代码启用保持。保持检查
与执行锁目前也不构成可靠的并发保证；不能承诺配置后自动动作绝不会覆盖手动命令。
实际设备版本和 unit 环境须单独核对。

## 上联网络

业务 IP 和网关由使用者提供。现网地址和示例均是特定站点的历史信息，不应复制到其他
机器。识别具体接口、已有 NetworkManager 配置和远程回退通道后再考虑变更；`config-uplink.sh`
会修改网络配置，运行前需单独审查其行为。主站、国内中转、设备与两套 WG 的职责见
拓扑台账和 skill 6。原有 2026-10 现场接线和 PDU 事故记录仅是历史经验，不能代替
当前设备状态验证。
