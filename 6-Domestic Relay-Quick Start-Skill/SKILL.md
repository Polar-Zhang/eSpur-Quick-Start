# 国内中转与两套 WireGuard

先阅读 [全网拓扑](../2-Overlay%20NetWork-Quick%20Start-Skill/references/topology.md)。以下是 2026-11-15 台账，不等于远端实时状态；操作前核对目标主机和已生效配置。

北京中转 `8.134.215.146` 同时承担：

- eSpur WG hub：`espur-wg0`、`10.66.66.1/24`、UDP 51822。
- 用户自有 WG hub：`wg0`、`10.10.10.1/24`、UDP 51820；这是独立系统，不能覆盖或重启。
- TCP 443/8443 透明转发到新加坡主站 443，用于受限站点 HTTPS 遥测和指令；TCP 8444 透传到主站 SSH 22。SSH 本身不是 TLS。

lab-01 按台账以 hosts 指向北京，再通过 HTTPS 上报；Studio 和 Studio-Backup 直连主站。WG 是管理网络，上报不通过 WG。旧 `51821/udp → 新加坡:51820`、新加坡双端口 hub 和 22022 反连方案均已退役，不能照搬旧命令。

## 排查及变更边界

1. 先区分问题是本地网络、到北京中转、北京到新加坡、WG 还是设备/平台处理。ICMP 或其他目的地的 UDP 通断不能单独证明目标端口的安全组状况。
2. 在已授权的主机分别只读检查接口、路由、监听、服务和日志；核实平台域名解析/hosts 与受限节点的预期是否一致。
3. 中转上的 Nginx 配置和两套 WG 可能被其他业务共用。先检查完整现状、配置来源和恢复通道；不得用旧模板整文件覆盖、追加重复 hosts 项、自动切换 Endpoint 或重启不相关接口。
4. 如需新增节点或迁移，分别规划 HTTPS 透传、eSpur WG 和用户自有 WG；明确端口、路由、MTU、安全组、受影响节点和回滚步骤，再在授权范围内操作。
5. 不保证断网数据均可补传：设备上报分支、内存缓存上限和单口失败行为不同；按实际设备版本和数据验证缺口。

具体 peer 和网段按 [组网 Skill](../2-Overlay%20NetWork-Quick%20Start-Skill/SKILL.md) 与拓扑台账核对；不要使用旧 `join_mesh.sh` 或旧自动看门狗。
